# 谁是人类

**一桌 AI，只有你是人。** 运行在[七牛灵矽 Linx](https://linx.qiniu.com/)上的网页版语音派对游戏：你坐在 5 号，模仿模型说话，争取不被四位 AI 玩家投票识破。

## 30 秒看懂玩法

1. 选场景、难度和化名，开始本局。模型年会、AI 相亲角、深夜客服值班室三个场景共 18 张话题卡，每局两轮。
2. 群主出题，四位 AI 先发言、你最后回答；第二轮只留两位 AI 发言。不会说可点「给我灵感」，照着 AI 腔模仿。
3. 互盘时 AI 引用你的原话指控，你可以打字打断、辩护，再投一个座位。
4. 群主报票、揭晓身份和人味分；结局可下载 PNG 分享卡、再来一局。分享卡没有二维码。

当前文字版和语音版都由玩家打字并确认；「按住说话」是占位，不录音、不上传录音。语音版为 AI 和群主增加逐角色音色。

## 产品价值与边界

面向想一个人开一桌、或在聚会中轮流挑战的玩家。题卡给话题，AI 先答给示范，互盘引用原话制造笑点，投票和分享卡形成完整反馈，降低「不知道聊什么」的门槛。当前交付是本机单玩家网页，进度存在服务端内存，重启清空。

面向灵矽 AI 玩具、智能音箱厂商，本作可作为语音互动内容的验证样例：同一条连接轮流演一桌角色，服务端控制输赢，固定台词可复用。硬件适配、品牌题库、云端分享分发属于后续产品方向，尚未实现；没有用户增长、付费或商业收入数据。

## 快速开始

环境要求：**Node.js 24**。在仓库根目录运行。

### 文字版：无需密钥

```bash
npm ci
npm start
```

打开 http://127.0.0.1:4173/mixin 。AI 台词使用服务端脚本兜底，不调用大模型；玩家打字，不申请麦克风，不连接灵矽。

### 语音版：灵矽配音

先执行 `npm ci`，在灵矽控制台绑定设备与智能体，使用 `mixin-prompts.mjs` 的 `agentPrompt`，保留 `{{counter_brief}}`；模型负责照念【台词】及角色即兴，不调用工具。

```bash
export LINX_DEVICE_JSON='<设备 JSON 正文或文件路径>'
export LINX_API_KEY='<API key>'
npm run play:voice
```

打开 http://127.0.0.1:4173/mixin ，允许浏览器播放声音；玩家仍然打字并确认。`PORT` 可修改端口。没有可用凭据时命令退回文字版；`npm start` 始终是文字版。

首次后台预合成需预留几分钟，64 条清单的全量耗时随平台响应变化，不保证固定时长。预合成是增量的：已有相同文本、音色且文件存在的条目会跳过，中断后下次接着补；开局可打断预合成，结局后自动续跑。音频写入被忽略的 `public/mixin/audio/`，不要提交。

**不要同时打开首页的语音，也不要设置 `LINX_WS_URL`。** 走设备配置与 API key 的正常连接流程；同一设备只允许一条 Linx WSS，预合成和对局共用连接。凭据只在运行时注入，不写入仓库、日志或 PR。

## AI 在游戏里做什么

- **角色演出**：`mixin-roles.mjs` 定义柯老师的谨慎免责声明、阿斯哥的三步宏图、深思哥的约束思考、包包的口语务实、小四的短句胡说；每局四位 AI 上桌。语音版按角色切音色，角色即兴最多两句；文字版用脚本演出。
- **可复核判定**：`humanity.mjs` 累加玩家发言特征得到人味分，`aiScore = clamp(100 - 人味分 × 10, 0, 100)`。生活细节、情绪等加分，AI 腔、分点、免责声明等减分，再按难度映射四张 AI 票。完整规则见[架构文档](docs/architecture.md#人味分)。这是确定性游戏规则，不是大模型判断真人的能力评测。
- **关键结果由服务端确定**：发言顺序、原话引用、票型、胜负、结局模板和分享卡都由服务端控制，LLM 负责配音与角色即兴。

## 常见问题

- **设备被踢 / 断连**：每台设备只能有一条连接，第二条会把第一条踢掉。关闭其它试玩程序和首页语音，预合成不要另起进程与对局抢设备。
- **只有字幕没声音**：合成超时、空音频或断线恢复失败时会退回字幕；结算仍由服务端完成。检查连接和浏览器播放权限。
- **预合成没跑完**：前几句会实时合成，等待慢一些；无需等全量完成才能开局，下次会继续补。

## 保留入口：你是什么人类模型？

六道生活题，自由语音回答，最后获得一张有原话证据的“人类模型卡”。Linx 提供实时语音、模型回复和工具调用；自己的网页负责题目、确认和报告展示。

型号采用 GPT / Astra、Claude、Gemini、DeepSeek、通义千问、Kimi、豆包和虚构的4B小模型。型号表示回答风格，配一句风格副标（如“群聊后勤部长”）；“夯爆了、顶级、人上人、NPC、拉完了”只评价本次表现，不是真实品牌性能排名。

档位不是模型自由心证：后端用六题原话做确定性事实台账（澄清未知、四要素写入/热更新/召回、多约束安排），算出能力格条（幻觉3格、上下文4格、指令3格）和允许档位，越界评级会被拒绝；证据不足只给中间档并标“待测”。最终模型卡含能力格条、逐项覆盖的事实核查表（3×4 信息要素矩阵给出覆盖率 x/12，每题每个要素 ✓/✕ 可追溯）、型号规格栏（上下文窗口/推理模式/推荐部署/暂缓部署）和逐字原话证据。模型不得在语音里念操作过程，服务端还会对“我先查看状态”这类过程语做句子级静音。

### 旧版试玩

Node.js 24，执行 `npm ci`、`npm start`，打开 http://127.0.0.1:4173/ 。点击开始，接通测试员，按住按钮或空格说话，松开发送；也可输入文字。检查转写后点击确认，六题后生成报告。

首次启动会生成被忽略的 `.linx-device.json`。设备需绑定 Linx 智能体，角色提示使用 `benchmark.mjs` 的 `agentPrompt`，保留 `{{counter_brief}}`。令牌只在服务端内存中使用。

## 验证命令

- `npm run check`：语法检查。
- `npm test`：规则、证据校验、音频资源、协议与HTTP测试。
- `npm run test:rules`：`game.mjs`、`mixin-game.mjs` 和 `humanity.mjs` 的分支覆盖率至少 90%。
- `npm run test:coverage`：自有服务端行覆盖率至少80%。
- `npm run sim`：离线跑完一局「谁是人类」，默认是演示局，难度锁在普通。`npm run sim -- --stealth` 看潜伏成功。`--difficulty` 会关掉演示锁。两条都不申请麦克风，不连接灵矽。
- `npm run smoke:linx`：六题真实平台链路测试，会使用平台额度；输入为合成文字，输出包含真实语音，不替代真人麦克风验收。
- `npm run probe:voice`：灵矽语音能力探针。凭据只读本机 `.linx-device.json` 或环境变量，结果写入已忽略的 `probe-results/`。没有真实凭据时用 `npm test` 里的模拟消息流验证测量逻辑。

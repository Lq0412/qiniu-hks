# 人类模型测评站：语音问答与生活化模型报告

状态：新方向设计稿，2026-10-24。依据用户提出的“用模型评测梗测人”想法。先评审题目和报告效果；当前办事游戏尚未被此设计替换。

## 核心体验

开场：“欢迎参加人类模型基准测试。全程开口回答，不需要懂AI。测完告诉你：你是深度推理旗舰，还是情绪驱动的小模型。”

一个有冷幽默的测试员，通过六个短问题构成一次约3–5分钟的体验。题目是群聊、外卖、同事、聚餐等日常情境。回答途中只作短反馈，不泄露整套评分；最后生成一张有具体证据、能截图分享的“模型卡”。

核心笑点：把大家熟悉的生活行为，翻译成AI术语。想太多可以叫过度推理，忘了别人不吃香菜叫上下文丢失；但想象力不能自动算幻觉，话多也不能自动算能力差。报告评价本局回答，不是智力、心理诊断或实际模型性能测量。

## 题目初稿

| 编号 | 测试员实际提问 | 观察点 |
|---|---|---|
| Q1 群聊补全 | 群里有人说“明天老地方，懂的都懂”。你刚进群，不知道老地方是哪。你会怎么回？ | 会不会把不知道的地点说成已知事实；澄清、猜测和提议必须区分 |
| Q2 写入上下文 | 你负责约饭：周五晚上七点半，去小馆吃火锅，同行的小周不吃香菜。你会怎么把这件事发到群里？ | 是否保留时间、地点、人物饮食限制；这四项进入事实台账 |
| Q3 脑内推理 | 同事只告诉你“老板刚刚问起你了”，没有别的信息。你觉得可能是什么事，准备怎么办？ | 是否将猜想当确定结论；推理倾向和行动是否与信息量相称，不按乐观/悲观打分 |
| Q4 热更新 | 刚才的聚餐改到周六晚上八点，其他都不变。请重新发一条群通知，最多两句话。 | 更新新时间、保留地点和小周的限制、遵守输出约束 |
| Q5 多约束安排 | 假设你在家收到外卖员电话：三分钟后到门口；室友五分钟后回来，也没有带钥匙。你只能下楼一次，不能把门敞着。你会先怎么沟通，再安排这件事？ | 是否提出可行方案、主动补充必要条件；不存在唯一标准答案，可询问外卖能否短等或经同意放指定处 |
| Q6 压缩与召回 | 最后，用一句话告诉我：这顿饭什么时候、去哪吃，还有谁有什么忌口？ | 对Q2/Q4信息的最终召回；“一句话”不等于必须固定字数 |

题目里的聚餐不是用户真实行程，不调用日历或外部服务。首版不做随机出题，以便检查同一条件下的判定一致性。

## 反馈语气

- Q1主动询问地点：“很好，你没有对‘老地方’进行创造性地理补全。”
- Q3提出多种猜测并保留不确定：“检测到脑内开了四个分支，好消息是你还没把其中一个当事实。”
- Q4漏掉香菜：“时间热更新成功。有一项旧约束可能被上下文压缩掉了。”

反馈不编造用户没有说过的话；语音转写不清楚时先确认。用户明确在玩梗或做假设时，不能据此判定事实错误。

## 报告结构

1. 模型昵称与一句结论：如“脑内剧场 MoE”“一句话4B”“认真过载 Pro”“长文解释型”。可以用用户提出的Astra型、Claude型等趣味标签，但明确是本作虚构映射，不冒充真实模型评测。
2. 三项核心观察：信息脑补、上下文保持、约束遵循；每项展示题目、回答原句、依据和不确定性。
3. 表达与推理风格：先问再答/快速决策/展开很多分支/习惯补充说明。风格不组成智力排行榜。
4. 响应节奏和输出量：测本地“题目播完→用户开始回答”的间隔、回答时长与转写字数；不要把ASR、网络、LLM和TTS等待算成用户思考时间。没有可靠时序就不生成速度数值。
5. 生活化吐槽与“推荐部署场景”：群聊澄清、点外卖、解释迟到等。既指出破绽，也保留优点。
6. 一条具体建议：必须能从本次回答推出，避免通用鸡汤。

不展示无依据的精确“幻觉率87.3%”或“智商相当于某模型”。首版用低/中/高或0–5格的娱乐指数；证据不足写“待测”。如果以后显示百分比，必须说明分母和计算规则，例如4项已知约束中保持3项，显示“本局约束保持3/4”，而不是抽象能力达到75%。

## 报告样例（虚构回答，用于评审文案）

假设玩家Q1说“不知道老地方在哪，我先问定位”；Q3说“他是不是准备开除我？也可能只是找我拿文件，我先问同事原话”；Q4正确更新周六八点，但没有保留小周不吃香菜；Q6依然漏掉忌口。

**鉴定结果：脑内剧场 MoE · 生活推理版**

“你不是没逻辑，你是在一句‘老板找你’里，提前开了四个项目。所幸，你还知道先核实需求。”

- 信息脑补：低。你把“被开除”作为猜测，并主动核实，没有将猜测当作事实。
- 上下文保持：出现约束丢失。时间更新成功，小周的香菜禁区在Q4/Q6消失了。证据来自这两轮回答，不是随机抽签。
- 指令遵循：本次两句话/一句话要求按实际回答检查，不能只因内容遗漏就同时扣格式分。
- 推理风格：分支很多，仍愿意回到证据。吐槽：“深度思考已启动，先别把公司解散了。”
- 生活补丁：“重要忌口请写入外部记忆。别让朋友成为你上下文压缩的受害者。”
- 推荐部署：群聊找定位、出门前核对清单。暂缓独立部署：全桌点菜。

“一句话4B”也可以是好结果：“参数不多，事情办妥。别人还在分析老板的语气，你已经问到了他找你干什么。”模型标签描述风格，不能把小模型等同于笨。

## Linx实现方案

沿用已验证的自己的网页→Node后端→Linx WSS/PCM与端侧MCP，不重新建设音频基础设施。

- Linx测试员：朗读固定题目、听取自由回答、必要时确认转写，控制简短反馈。
- 后端：保管题目顺序、事实台账、确认后的回答和本地时序；工具调用不能让模型跳题或覆盖历史回答。
- 报告生成：最后一次由LLM根据完整确认记录返回结构化报告；语音链路中的模型可通过报告工具提交，后端校验题号和引用，再渲染。先验证该模型在当前平台上的工具输出长度和格式，不假设存在未核实的单独报告API。
- 事实核对与文案分开：先生成带来源的观察，再写吐槽。每个引用必须逐字存在于确认回答中；引用不存在则拒绝该条报告。不能只要求LLM“给点有趣的分数”。
- 页面：开场、单题语音会话、可确认的转写、等待分析、结果模型卡。不给用户预置答题选项。

## 首版验收

- 六题可通过真实语音完成；转写不清楚可重答或确认，拒绝作答可跳过并标记缺失。
- 同一回答不重复记录；重开和晚到响应不串局。
- 报告至少引用两条真实回答；引用和事实保持检查可独立验证。
- 保留不确定性的推测不算已确认幻觉；不凭回答时长推断真实智力。
- 不完整数据不补造能力结论，生成失败明确显示失败并允许重试。
- 题目和样例先人工试玩，检查是否有笑点；再验证功能、时序、报告质量和截图表现。

# 灵矽AI（七牛 xrobo）平台技术精读 —— 服务「2 天单人纯 Web 语音游戏」黑客松

> 精读时间：2026-10-24。所有结论标注 **【文档已证实】** 或 **【推断/待验证】**。
> 文档根：https://linx.qiniu.com/docs/xrobot ｜ 控制台：https://xrobo.qiniu.com/ ｜ 官网：https://linx.qiniu.com/
> 协议本质：灵矽设备侧协议 = 开源 **xiaozhi-esp32** 协议族（Base Path `/xiaozhi`、OTA `/v1/ota/`、WS `/v1/ws/`），不是私有黑盒。

## 0. 一页速览（先看这个）

- 平台原生就是「**1 条 WS 连接 = 1 个智能体**」，但握手时可用 **`X-Agent-ID` 请求头** 指定本次连接用哪个智能体，会话内还能用 **`listen.agent_params.voice`** 换音色、用 **`hello.agent_params.custom_replace_prompt`** 注入人设占位符。【文档已证实】
- **没有官方浏览器 Web SDK**。官方客户端 demo 是 C++（Linux/macOS，ALSA/PortAudio），不是 Web。【文档已证实】
- 控制台自带「**网页体验 / 拨打**」：浏览器授权麦克风即可与单个智能体实时语音，**按住说话（push-to-talk）**，0 行代码。【文档已证实】
- 业务侧要确定性状态机（狼人杀），最省事的不是 MCP，而是把智能体的「大脑」换成你自己的服务：自定义 OpenAI 兼容模型（`POST /v1/models/llm` 填你自己的 `base_url`）或第三方业务接入（HTTP POST + SSE）。【文档已证实】
- 计量 = **设备会话时长 ×（1 + 大模型计时系数 + 音色计时系数）**，按秒扣，不区分 ASR/LLM/TTS 分别计费。【文档已证实】

## 1.【最高优先】无硬件纯 Web 演示，哪条路最快？

### (a) 控制台内置「试玩/预览/调试」—— 网页体验拨打 【文档已证实】

- 入口：控制台 → 智能体管理 → 进入某智能体配置页 → 右侧「**网页体验**」面板 → 「**点击拨打 / 拨打**」绿色电话按钮。
  - 文档：https://linx.qiniu.com/docs/xrobot/guide/agent-config （§9.3 网页体验）
  - 快速入门截图里顶部还有「**模拟测试**」按钮：https://linx.qiniu.com/docs/xrobot/guide/quick-start
- 行为原文要点：
  - 「准备好麦克风与扬声器后，点击『拨打』，按浏览器提示允许使用麦克风。」
  - 「**按住说话、松开静音**：按住麦克风按钮期间讲话，松开后恢复静音。只接通后直接讲话，可能没有发送语音。」→ **是 push-to-talk，不是全双工自由对话**。
  - 「点击『拨打』时，页面会先保存当前配置，再建立连接。」
  - 「挂断：结束当前测试连接。」
- 结论：**0 代码、5 分钟**即可在浏览器里用真实麦克风跟真实智能体对话，用于「证明平台可用 + 快速试听每个 AI 玩家音色/人设」极快。
- 局限：**一次只能拨一个智能体**、push-to-talk、无法编排游戏流程、无法被你的游戏 UI 控制。**不能用来跑狼人杀，只能用来单点验证。**
- 单人工时：**5 分钟**（仅验证）。

### (b) 官方 Web Demo / SDK / 开源示例 【文档已证实：无官方 Web 版】

- 官方「客户端 demo」= **Linx Audio Client，C++ 跨平台（Linux ALSA / macOS PortAudio）**，GitHub：**https://github.com/sunqirui1987/linx-linux**
  - 文档：https://linx.qiniu.com/docs/xrobot/guide/client-demo
  - 关键参数（与 Web 端可直接复用）：`SAMPLE_RATE=16000`、`CHANNELS=1`、`CHUNK=960`、Opus、帧 60ms、`ws://xrobo-io.qiniuapi.com/v1/ws/`。
  - **不是浏览器工程，不能直接跑 Web**；但它是「hello/listen/tts/二进制 Opus」状态机的权威参考实现。
- 官方组织 `Qiniu-linx` 公开仓库页显示「0 public repositories」；文档引用的后台仓库是 **https://github.com/Qiniu-linx/linx-app-backend**（灵矽 App 小程序+管理后台，Docker Compose 部署，文档 https://lingxiwmp.qiniu.com/docs/backend/ ）——是小程序/后台，**不是浏览器语音 SDK**。
- npm：**未发现官方 `@qiniu/linx` 浏览器 SDK**【推断/待验证：可 `npm search` 再确认】。
- 旁证：协议与开源 `xiaozhi-esp32-server` 同源（Gitee 上有大量社区 Web/服务端实现），理论上可移植社区 `xiaozhi-web` 前端，但**非官方、字段可能漂移**，2 天内不建议赌。
- 单人工时：**0**（无可直接复用的 Web 工程）。

### (c) 自己写 WebSocket（`wss://xrobo-io.qiniuapi.com/v1/ws/`）【文档已证实】

- 地址：`wss://xrobo-io.qiniuapi.com/v1/ws/`（WS 明文 `ws://...` 仅内网）。文档：https://linx.qiniu.com/docs/xrobot/platform/websocket
- 建连握手请求头（原文）：
  ```
  Authorization: Bearer <token>
  Protocol-Version: 1
  Device-Id: <MAC 或伪 MAC>
  Client-Id: <UUID v4>
  X-Agent-ID: <agent_id>        # 可选，指定本次连接用哪个智能体
  ```
- **token 从哪来（浏览器/服务端都要走这一步）**：OTA 协议 https://linx.qiniu.com/docs/xrobot/platform/OTA
  1. `POST https://xrobo.qiniuapi.com/v1/ota/`，请求头带 `Device-Id`(伪 MAC)、`Client-Id`(UUID)、`Activation-Version:1`、`User-Agent: web-demo/1.0.0`。
  2. 未绑定 → 返回 `activation.code`（6 位数字，如 `608303`）；在控制台「设备管理 → 添加设备 → 输入验证码」绑定一次。
  3. `POST /v1/ota/activate`（轮询，已绑定返回纯文本 `success`）；再次 `POST /v1/ota/` → 返回 `websocket.url` + `websocket.token`。
  4. 用该 token 连 WS。
  - 注：文档 OTA 示例的 User-Agent 就叫 `xiaoling-web-test/1.0.0`，**说明平台本就预期有 Web 测试客户端**。
- **前端音频链路（浏览器必须自研）**：
  - 上行（麦克风）：`getUserMedia` → AudioWorklet 拿到 PCM → 重采样到 **16kHz/单声道/16bit** → Opus 编码 → 二进制帧（**推荐 frame_duration=60ms**，或 PCM：`bit_depth:16, frame_duration:20, frame_size:320`）。
  - 下行（TTS）：服务端发 **Opus / 16k 或 24k / 单声道 / 帧 20|40|60ms** 二进制 → 浏览器 Opus 解码 → WebAudio `AudioBufferSourceNode` 排队播放；`tts.state=start/stop/sentence_start` 控制开关，`is_aborted=true` 立即清缓冲。
  - 浏览器没有原生裸 Opus 帧编解码，需引入 wasm（如 `opusscript` / `@discordjs/opus` wasm 版）或 WebCodecs。**这是纯 Web 方案的主要工作量。**
- 浏览器音频格式结论：**上行 opus 16kHz mono 60ms（或 pcm_s16le 16kHz 20ms/320 样本）；下行 opus 24kHz mono 20–60ms**。【文档已证实】
- 控制消息（JSON 文本帧）：`hello` → `listen{state:start,mode:realtime}` 开始发音频；收 `stt`(识别文本)、`llm`(emotion/action 表情)、`tts`(状态)；打断 `abort`。【文档已证实】
- 单人工时：浏览器最小可用语音环（OTA+握手+hello+listen+Opus 编解码+播放队列）≈ **6–10 小时**；其中 Opus wasm 编解码与播放抖动缓冲占一半。

### Q1 推荐（2 天黑客松）

> **最快上手段一句话**：先花 5 分钟用控制台「网页体验/拨打」逐个验证 3 个 AI 玩家的音色与人设；正式演示用「**一个自研极简 Web 客户端（c 路线）+ 你的 FastAPI 编排器**」，前端只做「真人玩家麦克风 + 游戏 UI」，AI 玩家的发声交给平台 TTS。不要等官方 Web SDK——它不存在。

- 前端音频链路：**需要自研**（浏览器无官方 SDK），但可极简化：真人端用 push-to-talk（按住说话）即可，省掉全双工 barge-in 的复杂状态机。
- 工时：控制台验证 5 min；自研 Web 客户端（push-to-talk + 游戏 UI）6–10h；FastAPI 编排器见 Q2/Q3。

## 2. 多人 / 多智能体 —— 最小狼人杀（1 真人 + 3 AI）可行性

### 原生会话模型 【文档已证实】

- 默认「**1 设备(Device-Id) ↔ 1 智能体**」：WS 握手 `Device-Id` 决定设备绑定到哪个智能体。
- **但有两个原生开关突破这个 1:1：**
  1. **`X-Agent-ID` 请求头（握手时）**：「在 WebSocket 握手 Header 中传入 `X-Agent-ID: <agent_id>`，此参数决定当前连接使用哪个智能体配置。」
     - 文档：https://linx.qiniu.com/docs/xrobot/platform/agent-voice-switch
  2. **会话内换音色**：发 `listen` 消息带 `agent_params.voice = {id, volume, speed, pitch, emotion}`，「只改 TTS 音色，不切换智能体，默认保持当前会话上下文连续」。
     - 官方示例就是多人格：`text:"你当前身份是李白，结合之前你杜甫的身份，开始对话吧"` + 换 voice.id。
- **注入私有信息（身份牌）**：`hello` 带 `agent_params.custom_replace_prompt`，把智能体 system prompt 里的 `{{占位符}}` 替换成运行时值。
  - 文档：https://linx.qiniu.com/docs/xrobot/platform/websocket （「Hello 消息扩展：智能体提示词替换」）
  - 示例：`custom_replace_prompt: {assistant_title:"小牛牛", user_name:"张三", ...}`。注意原文警告「**不要用 assistant_name，这个变量已被占用**」。

### 第三方业务接入体系（third-app）【文档已证实】

文档：https://linx.qiniu.com/docs/xrobot/guide/third-app

- 三段架构：**设备端(WS) ↔ 灵矽平台(ASR/TTS/路由) ↔ 业务服务(HTTP POST + SSE)**。
- **Chat 对话模式**：平台把你的业务服务当「大模型」。
  - 平台 → 业务服务：`POST http://your-domain/api/chat/stream`，`Content-Type: application/json`，`Accept: text/event-stream`，`Authorization: Bearer your_api_token`，body：
    ```json
    {"auth":{"device_id":"669C4BDA13EA"},"type":"chat",
     "details":{"msg":"用户说的话(ASR后文字)","session_id":"session_12345","timestamp":1640995200000}}
    ```
  - 业务服务 SSE 回：
    ```
    data: {"event":"message","type":"chat","session_id":"...","details":{"answer":"...","tts_provider":"huoshan","voice_type":"BV051_streaming","speed_ratio":1.0,"pitch_ratio":1.0}}
    data: {"event":"message_end","session_id":"..."}
    ```
  - **关键**：SSE 响应里可逐句指定 `voice_type`（音色）和 `tts_provider`——即**业务服务可以控制这一句话用哪个音色播**。
- **透传消息模式**：不满足 chat 条件的消息，平台**原样 copy 转发**给业务服务；业务 SSE 响应再被包成 WS `custom` 消息下发：
  ```json
  {"session_id":"...","type":"custom","payload":{"source":"business_service",
   "original_request_type":"report|reset|get","business_response":{...},"timestamp":...}}
  ```
  - 设备端上行 custom：`{session_id, type:"custom", payload:{auth, type:"report", details:{events:[...], session_id, timestamp}}}`。
- **判定规则（原文）**：`event=="message" AND type=="chat"` → 平台做 TTS；**其他类型一律直接透传**，平台不解析内容。

### 一个业务服务能否持有多个 agent / 多条 WS 并按状态机路由？

- **能（架构层）**：业务服务（FastAPI）就是个普通程序，可同时开多条到 `wss://xrobo-io.qiniuapi.com/v1/ws/` 的连接，每条带不同 `X-Agent-ID`。【架构可行=文档已证实 X-Agent-ID 存在；「同 token/同伪 MAC 能否并发多条」**待验证**，兜底：给每个 AI 玩家 provision 一个伪 MAC（共 3–4 个）。】
- **多真人汇入**：每个真人开一个浏览器 WS（各自伪 MAC），平台按 `auth.device_id` / `session_id` 隔离会话；业务服务按 `session_id` 路由。【文档已证实 session_id 隔离机制】

### 推荐落地架构（1 真人 + 3 AI，有文档依据）

```
┌─────────────┐  WSS   ┌──────────────────────────────────────────┐
│ 浏览器(真人) │◄──────►│ 灵矽平台 (ASR/TTS/路由)                    │
│ push-to-talk │        │  wss://xrobo-io.qiniuapi.com/v1/ws/       │
└─────────────┘        └───────▲───────────────▲──────────────────┘
                               │ 4 条 WS(各带 X-Agent-ID)
              ┌────────────────┴────────────────┴───────────────┐
              │  FastAPI 狼人杀编排器（你的业务服务 = 状态机 + 大脑）│
              │  • 夜晚/白天/杀人/查验/发言/投票/出局 状态机        │
              │  • WS#1 X-Agent-ID=AI玩家A(狼) voice=音色A        │
              │  • WS#2 X-Agent-ID=AI玩家B(民) voice=音色B        │
              │  • WS#3 X-Agent-ID=AI玩家C(神) voice=音色C        │
              │  • 用 custom_replace_prompt 给每人注入私有身份牌    │
              │  • 想让某AI发言 → 触发其会话LLM / 或走 third-app   │
              │    chat SSE 直接给文案 + voice_type              │
              └─────────────────────────────────────────────────┘
```

- **为什么不用「一个连接 + 运行时换 voice/prompt」硬切**：虽然 `listen.agent_params.voice` 和 `custom_replace_prompt` 支持换声/换人设，但**上下文是同一条会话**，狼人要求「3 个 AI 互相不知私密信息」，共用一条会话会串味。**推荐 3 条独立 WS（3 个独立智能体）**。
- **让 AI「按剧本说话」的最稳姿势**：不要指望平台 LLM 自由发挥。把每个 AI 智能体的 LLM 配成「**指向你 FastAPI 的 OpenAI 兼容端点**」（见 Q3），或走 third-app chat 模式由你回 `answer`+`voice_type`。这样狼人杀的「夜晚结果公布、投票台词」完全由你的状态机决定，平台只负责「把这句话用对应音色念出来 + 把真人的话转成文字」。
- 单人工时：FastAPI 编排器（状态机 + 多 WS 管理 + SSE/OpenAI 适配）≈ **8–14 小时**；伪 MAC 批量 provision + 绑定 ≈ **30–60 分钟**。

## 3. 确定性状态机（夜/昼/闭眼/杀人/查验/发言/投票/出局）怎么落地

### 方案 A：云端 MCP（SSE 外部工具）【文档已证实】

文档：https://linx.qiniu.com/docs/xrobot/guide/mcp-store

- 机制：你自建一个 **SSE 型 MCP Server**（标准 Model Context Protocol over SSE），在控制台「自定义 MCP」注册：
  - `POST /v1/mcp-store/servers`，`config_schema.sse.url = https://你的域/sse`，普通用户只能 `is_private:true`。
  - 再 `POST /v1/mcps` 开通（填 url/header），`PUT /v1/agents/{agent_id}/mcps` 绑定到智能体。
- 工具定义（标准 JSON Schema）：`GET /v1/mcps/{id}/tools` 返回 `[{name, description, inputSchema:{type:object,properties:{...},required:[...]}}]`；调用 `POST /v1/mcps/{id}/toolcall`。
  - 例：`night_kill(target:"player_id")`、`vote(target:"player_id")`、`announce(event:"...")`。
- **关键缺点**：MCP 工具是 **LLM 自主决定何时调用**（「Agent 在对话时 LLM 自动调用」），不是确定性触发。狼人杀的「夜晚必须闭眼中立裁判」若靠 LLM 自觉调用，会漏调/乱调。**适合做「只读信息查询」，不适合做强流程裁判。**
- 额外：`GET /v1/mcpproxy/token` → `wss://.../v1/mcpproxy/connect?token=...`（30 天有效，代理 stdio/sse）。

### 方案 B（推荐）：你的业务服务当大脑 + 状态机硬驱动【文档已证实】

- 把智能体 LLM 指向你自己：`POST /v1/models/llm` 创建 OpenAI 兼容模型
  ```json
  {"name":"werewolf-orchestrator","config":{"type":"openai",
   "base_url":"https://你的域/v1","api_key":"EMPTY","model_name":"werewolf"}}
  ```
  文档：https://linx.qiniu.com/docs/xrobot/api/llm
- 或走 third-app chat SSE（见 Q2），由你回 `answer`。
- 这样「夜晚/白天」由你的状态机切，「杀谁/验谁」由你（或把真人/AI 的发言喂给你自己的 LLM 做决策）算，平台只做 ASR+TTS。**LLM 不会乱判，因为裁判逻辑根本不在 LLM 里。**

### 2 天内哪种最省事？

- **选 B**：不碰 MCP 的工具编排心智，FastAPI 里 `if phase=="night": ...` 直接写。MCP 仅在需要「让 AI 自己查公共信息板」时再加一个只读工具。
- 工时：确定性状态机 + 自定义 LLM/SSE 适配 ≈ **6–10 小时**；若额外做云端 MCP ≈ **+2–3 小时**（FastAPI 起个标准 MCP SSE 服务）。

## 4. 音色与人设（多 AI 玩家区分度的关键）

### 人设 Prompt 【文档已证实】

- 每个智能体独立 `systemPrompt`（角色介绍，**最长 6000 字符**），字段 `[角色设定]/[核心特征]/[交互指南]` 模板。
- 创建/更新：`POST /xiaozhi/agent`、`PUT /xiaozhi/agent/{id}` 的 `systemPrompt` 字段。文档：https://linx.qiniu.com/docs/xrobot/api/agent
- 运行时注入私有身份：`hello.agent_params.custom_replace_prompt`（见 Q2）。

### 音色（3 条路）【文档已证实】

1. **配音广场选音**：控制台「选择音色」试听，搜索/按语言分类；每个智能体 `ttsVoiceId` 独立绑定。文档：agent-config §3.2。
2. **声音复刻**（音色克隆 API）：https://linx.qiniu.com/docs/xrobot/api/voice-clone
   - `POST /v1/voice-clones` body `{language:"zh", tier:"free|lite|pro"}` → 返回 `id`、`state:Init`。
   - `PUT /v1/voice-clones/{id}` body `{key:"https://.../sample.wav", name:"..."}` 发起训练 → `state:Training→Success`。
   - 训练音频建议 **20–30 秒**、清晰无噪；训练需几分钟到十几分钟；免费版仅 **zh/en**。
   - 格式：App FAQ 说支持 **MP3/WAV/M4A/AAC/FLAC，10–120 秒**（https://lingxiwmp.qiniu.com/docs/v1.2.5/app/faq.html ）。
   - 额度：`GET /v1/voice-clones/quota?tier=free` → `{available_count:8}`（示例值，以你账号为准）；复刻成功后有效期 1 年，可 `POST /v1/voice-clones/{id}/renewals` 续期。
3. **情感 TTS**：智能体 `extra.voice = {volume, speed, pitch, emotion, quality, enable_tts_emotion}`；控制台「多情绪变化」开关；运行时 `listen.agent_params.voice.emotion` 可逐句指定情绪（≤32 字符）。文档：api/agent + agent-voice-switch。

### 数量 / 审核限制

- **不同智能体能否绑定不同复刻音色**：**能**。`ttsVoiceId` 是智能体级字段，3 个 AI 玩家 = 3 个智能体 = 各自 `ttsVoiceId` 指向不同复刻音色。【文档已证实】
- 智能体数量上限：**文档未给出具体数字**【推断/待验证】；控制台可「新建智能体」自由添加。
- 复刻音色数量：按 tier 配额，`available_count` 实时查；免费档示例 8 个。【文档已证实（机制）/ 你的具体数以 quota 接口为准】
- 复刻审核：训练异步（分钟级），失败 `state:Failed` 可重训；未看到人工审核描述【推断/待验证：机器训练，无人工审核】。
- 声纹说话人（与音色无关）：每智能体最多 **20 个说话人**，总数受平台配额（https://lingxiwmp.qiniu.com/docs/app/guide/speaker.html ）。

- 单人工时：建 3 个智能体 + 3 段 20s 录音复刻 ≈ **1.5–2.5 小时**（含训练等待）；复刻赶时间就先用配音广场 3 个现成音色，**0 等待**。

## 5. 计量与省额度（100 小时怎么花）

文档：https://linx.qiniu.com/docs/xrobot/billing/resource-usage-billing

- **计价口径**：
  ```
  扣减倍率 = 1 + 大模型计时系数 + 音色计时系数
  扣减时长 = 设备会话时长 × 扣减倍率      （按秒计，不足 1 秒不计）
  ```
  - **按「设备会话连接时长」折算，不是按 ASR/LLM/TTS 各自用量、也不是按谁说话的秒数**。
  - 示例：系数 0.2(模型)+0.5(音色) → 倍率 1.7，会话 60 分钟扣 102 分钟。
  - 控制台智能体配置页底部「预计扣减倍率」实时显示当前模型+音色的倍率。
- **100 小时够不够**：1 条会话扣 = 真实连接时长 × 倍率。3 个 AI 玩家 = 3 条并发会话同时在跑 → **同时扣 3 份**。一场 10 分钟演示（倍率按 1.5 估）≈ 10×1.5×3 ≈ 45 分钟额度；加上真人 1 条 ≈ 60 分钟。**100 小时够演示几十场**，但调试期会连很多次空会话，要主动挂断。
- **省额度手段（文档明示）**：
  1. 选「计时系数 = 0」的便宜模型和音色（控制台音色名旁标 `+x`）。
  2. **不需要时立即结束会话**（`listen.stop` + 关 WS）；把 `extra.goodbye.idle_timeout_seconds` 设到 **60s**（范围 60–3600，默认 120），空闲自动断。
  3. 改配置只对「新会话」生效，调试时别挂着旧连接。
- **离线 mock / 纯文本调试**：
  - **平台没有文档化的「纯文本/离线 mock 通道」**【文档未提供=待验证】。
  - 变通：调试「大脑/状态机」时，把智能体 LLM 指向你本地 FastAPI 桩（不消耗平台 LLM 系数），但 **WS 会话时长仍扣**；最省的办法是**没在测语音时干脆别连 WS**，用 REST API（智能体增删改查）和单元测试把状态机测完。
  - REST 管理类 API（agent CRUD、mcp、voice-clones）是否计费：**文档未说明**【推断/待验证】，通常不计通话时长。

## 6. 协议与限制（建连/鉴权/全链路消息/时序）

### 6.1 鉴权 【文档已证实】

- REST：`Authorization: Bearer <api_key>`，api_key 在控制台「API Key 管理」创建。Base `https://xrobo.qiniu.com`。认证失败时 HTTP 仍 200，body `{code:401,msg:"未登录"}`。
  - 文档：https://linx.qiniu.com/docs/xrobot/api/index 、api/agent
- WS：握手头 `Authorization: Bearer <ota_token>`（token 由 OTA 已绑定设备下发）、`Device-Id`、`Client-Id`、`Protocol-Version:1`、可选 `X-Agent-ID`。

### 6.2 ASR→LLM→TTS 全链路消息类型 【文档已证实】

设备端→服务端：`hello`、`listen{state:start|stop|detect, mode:manual|auto|realtime}`、`abort{reason}`、二进制音频帧、`custom{payload}`。
服务端→设备端：`hello{session_id,audio_params}`、`stt{text}`、`llm{text emoji, emotion, action}`、`tts{state:start|stop|sentence_start, is_aborted}`、`notify{event:config_updated}`、`custom{payload}`、二进制 TTS 音频帧。

### 6.3 时序（最小一轮）

```
Browser/Orchestrator                灵矽平台
     │  WS 握手(Bearer,Device-Id,Client-Id,X-Agent-ID) │
     │───────────────────────────────────────────────►│
     │  hello{audio_params:opus/16k/60ms,features:{mcp}}│
     │───────────────────────────────────────────────►│
     │  ◄──── hello{session_id, audio_params:opus/24k} │
     │  listen{state:start, mode:realtime}             │
     │───────────────────────────────────────────────►│
     │  ──── 二进制 Opus 上行帧 (麦克风) ────────────►│
     │  ◄──────── stt{text:"我是预言家"}              │
     │  (LLM 由你业务服务/SSE 提供文案)               │
     │  ◄──────── tts{state:start}                   │
     │  ◄──────── 二进制 Opus 下行帧 (TTS)            │
     │  ◄──────── tts{state:sentence_start, text}     │
     │  ◄──────── tts{state:stop, is_aborted:false}   │
```

- **Barge-in（打断）**：`mode:"realtime"` 全双工，检测到人声自动打断 AI；或设备发 `abort{reason:"wake_word_detected"}`；收 `tts.stop` 且 `is_aborted:true` 时立即清音频缓冲。【文档已证实】

### 6.4 智能体 / 知识库 / LLM 管理 API 【文档已证实】

- 智能体：`GET /xiaozhi/agent/list`、`/search`、POST/PUT/DELETE `/xiaozhi/agent[/{id}]`、`PUT /v1/devices/{mac}/agent/{agent_id}`（切设备绑定，可 `disable_chat_history_migration`）。
- LLM：`POST /v1/models/llm`（OpenAI 兼容自定义模型）、`GET /v1/agents/models/llm`、`GET /v1/models/{id}/custom-config-schema`。
- 知识库：智能体 `datasetIds` 字段绑定（api/agent 更新对象里有）。
- MCP：见 Q3。

## A. 2 天单人可行性结论：最小狼人杀（1 真人 + 3 AI）能否落地？

**结论：能落地，但建议「大幅简化」并把裁判逻辑放在自己服务里，不要让平台 LLM 当裁判。**

- 平台原生能力完全够用：每个 AI 玩家 = 1 个独立智能体（独立人设 `systemPrompt` + 独立 `ttsVoiceId` 复刻音色），用 `X-Agent-ID` 在 WS 握手区分，用 `custom_replace_prompt` 下发私有身份牌。真人 = 浏览器 push-to-talk。
- **强烈建议砍到「3 人局 + 简化规则」**：1 狼人 / 1 预言家 / 1 村民，夜晚只有「狼杀人 + 预言家查验」，白天轮流发言 + 一轮投票。砍掉守卫/女巫/警长/遗言，避免状态机爆炸。
- **裁判别用 MCP 让 LLM 自觉调**：用 FastAPI 状态机 + 把 LLM 指向你自己的 SSE/OpenAI 端点，平台只做 ASR（听懂真人）+ TTS（用对应音色念 AI 台词）。

每块工时（单人，熟练全栈）：

| 模块 | 工时 |
|---|---|
| 控制台建 3 智能体 + 配人设/音色（先用配音广场免复刻） | 0.5–1 h |
| （可选）3 段录音复刻音色，等训练 | +1–1.5 h（可并行/省略） |
| 伪 MAC provision：OTA 取码 → 控制台绑定 → 拿 token | 0.5–1 h |
| 极简 Web 客户端：麦克风 push-to-talk + Opus 编解码 + 播放队列 + 游戏 UI | 6–10 h |
| FastAPI 编排器：狼人杀状态机 + 多 WS 管理 + SSE/OpenAI 适配 + 台词生成 | 8–14 h |
| 联调（打断/音色/串话/并发）+ 演示彩排 | 3–5 h |
| **合计** | **约 20–32 h（≈ 2 个全天，紧张但可行）** |

## B. 最大技术风险 TOP3 + 兜底

1. **浏览器裸 Opus 编解码坑（最大风险）**
   - 风险：平台只给 Opus 二进制帧（上行 16k/下行 24k），浏览器没有现成裸帧 Opus 编解码，wasm 体积、延迟、播放抖动都可能拖垮演示。
   - 兜底：① hello 里改 `format:"pcm"`（上行 PCM s16le 16k/20ms），**上行免编码**；下行仍需解 Opus，可用 `opusscript` wasm，预留 `play_buffer_duration=1000` 缓冲。② 实在不行，真人端用「录音文件 / 控制台网页体验」兜底，AI 玩家发言走服务端 WS（无浏览器音频问题）。

2. **多 AI 并发 WS 的鉴权/绑定不确定性**
   - 风险：`X-Agent-ID` 虽文档可指定智能体，但「同一个 OTA token / 同一个伪 MAC 能否同时开 3–4 条 WS」文档未写明，可能被 1:1 设备绑定限制。
   - 兜底：**给每个 AI 玩家单独 provision 一个伪 MAC 并分别绑定到对应智能体**（多花 30 分钟 OTA+绑定），从根上规避并发限制；演示前 1 小时先压测「同时开 4 条 WS 全双工」。

3. **LLM 当裁判导致流程失控 / 串信息**
   - 风险：若依赖平台 LLM 自由发言 + MCP 自觉调用，狼人可能说漏身份、夜晚动作漏触发，演示当场翻车。
   - 兜底：裁判逻辑 100% 在你的 FastAPI 状态机里；平台智能体的 LLM 指向你自己的端点（或 third-app SSE），AI 台词由你生成后让平台 TTS 念；私密身份用 `custom_replace_prompt` 只注入对应那一条连接，绝不共享同一会话上下文。
